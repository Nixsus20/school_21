# SQL 05. VIEW и MATERIALIZED VIEW

Здесь задача была в работе с виртуальными таблицами PostgreSQL. Обычное представление вычисляется из запроса, а материализованное хранит результат до обновления. На практике нужно было увидеть разницу между этими вариантами.

## Задания

| Файл | Условие |
| --- | --- |
| [ex00](src/ex00/day04_ex00.sql) | Создать два представления со списками мужчин и женщин из `person`. |
| [ex01](src/ex01/day04_ex01.sql) | Объединить данные из этих представлений в один отсортированный список. |
| [ex02](src/ex02/day04_ex02.sql) | Создать `v_generated_dates` с датами января 2022 года. |
| [ex03](src/ex03/day04_ex03.sql) | Через это представление найти даты, когда никто не посещал пиццерии. |
| [ex04](src/ex04/day04_ex04.sql) | Получить симметрическую разность множеств посетителей за два дня и оформить её как `v_symmetric_union`. |
| [ex05](src/ex05/day04_ex05.sql) | Создать представление с исходной ценой и ценой со скидкой 10% для заказанных пицц. |
| [ex06](src/ex06/day04_ex06.sql) | Создать материализованное представление с пиццериями, подходящими под запрос о посетителе и цене пиццы. |
| [ex07](src/ex07/day04_ex07.sql) | Добавить посещение, затем обновить материализованное представление через `REFRESH MATERIALIZED VIEW`. |
| [ex08](src/ex08/day04_ex08.sql) | Удалить представления и материализованное представление, созданные в предыдущих упражнениях. |

## Что ограничивало решение

Работа велась с конкретной схемой учебной БД и заданными именами `VIEW`. Для генератора дат требовался тип `DATE`. В ex05 скидка вычислялась непосредственно в SQL, с приведением итоговой цены к целому числу.

В ex07 идентификаторы посетителя и пиццерии нельзя было зашивать константами — значения нужно получать из данных. Порядок запуска тоже важен: ex07 зависит от созданного ранее материализованного представления, а ex08 удаляет полученные объекты.

## Как запускать

Скрипты лежат в `src/ex00`–`src/ex08`. Команда `make check` в корне репозитория выполняет их последовательно во временной базе PostgreSQL.
