# s21_decimal

Библиотека десятичной арифметики на C. Основная идея задания — хранить десятичное число в битовой структуре и выполнять вычисления, не полагаясь на обычное представление `float` для хранения десятичного значения.

## Условия задачи

Нужно было определить `s21_decimal` и написать:
- арифметику: сложение, вычитание, умножение, деление, остаток;
- сравнения двух чисел;
- преобразования между `int`, `float` и `decimal`;
- округление, отбрасывание дробной части и смену знака.

Важные ограничения:
- C11, `gcc`, статическая библиотека `s21_decimal.a`, публичный заголовок `s21_decimal.h`;
- число хранится в `int bits[4]`: 96 бит для целого значения, отдельные биты для знака и десятичного масштаба от 0 до 28;
- использовать `__int128` запрещалось; большой диапазон и переносы нужно обрабатывать вручную;
- требовались тесты на Check, целевое покрытие от 80% на функцию и HTML-отчёт `gcov/lcov`.

## Что есть в реализации

В [`src/`](src/) функции разбиты по группам:
- `arithmeticOps/` — арифметические действия;
- `bitOps/` — чтение и изменение битов, знак и масштаб;
- `comparsionOps/` — сравнения;
- `converseOps/` — преобразования типов;
- `other/` — округление и дополнительные операции;
- `support/` — общие вспомогательные функции;
- `tests/` — тестовый набор.

Помимо `s21_decimal` используется вспомогательная структура `s21_big_decimal` для промежуточных вычислений.

## Собрать и запустить тесты

```sh
cd src
make s21_decimal.a
make test
# отчёт о покрытии: make gcov_report
```

Нужны `gcc`, `make`, Check, а для отчёта — `lcov` и `genhtml`.

**Особенность текущего Makefile:** после запуска тестов стоит `|| true`. Поэтому код возврата `make test` не гарантирует успешное прохождение проверок: нужно смотреть вывод тестового исполняемого файла. Процент покрытия тоже не подтверждён отдельным запуском.

Командная работа в рамках Школы 21.
